# BL-054: Mod switch outside the App

Design proposed for owner review; implementation not started.

Target: the current cycle, before 0.6.0. Baseline: 0.6.0-alpha.8, commit `c57e9288`, branch `codex/mod-switch-shortcut`. This proposal adds Settings' owner-requested `生成APP外MOD开关` action and a generated `MOD开关` item. Opening it reverses the same master intent as the top bar's Enable Mods switch, operates on the same known installs, and reports the actual outcome. Generation itself never toggles Mods.

### Prevent web pages and other apps from silently toggling

**P:** Recommendations M1/W1 register no URL scheme, HTTP external link or custom file handler. A web page cannot use a `bamt:` URL to toggle. A deliberate local command line still can invoke the action, which is part of the user's desktop feature; the design is not a security boundary against software already executing as the same user.

**D:** Apple's and Microsoft's cited scheme guidance establishes that a scheme is an entry point for untrusted callers, not proof of a desktop-file double-click. **P:** If a URL alternative is later selected, all URL origins must enter a separate, confirmation-required mode. Allowlist one exact scheme/host/path, bound length, reject unknown fields, extra argv, malformed or repeated encoding and any caller-supplied file/data path. Never interpolate URI data into a shell or let URI arguments select the silent CLI action. Confirm the current operation in the App; cancellation does nothing. A capability embedded in a persistent URL is not sufficient: it can leak, be replayed or reach another registered handler. There is no reliable “only our `.webloc`/`.url` was clicked” check. These restrictions intentionally make URL options less suitable for this brief.

## 3. Recommended command lifecycle and behaviour

### Shared command protocol

All steps in this subsection are **P**, not current behaviour.

1. Add an action-mode combination guard in `launcher.main` before its current classic-flag dispatch, then parse the dedicated action in `webui/main.main` before full-window startup. Reject combinations with `--classic`, `--settings`, `--tab`, browser/serve/development token flags, arbitrary paths or unknown arguments. Reuse normal App settings/data-location selection and development isolation. The file means “invert once at admission”, not permanently Enable or Disable; it affects the same known installs as the master switch, including other known installs when the selected folder is missing.
2. Acquire the normal instance lock. For action mode require `instance.held`, not just `acquire() == True`, so the existing unwritable-directory fallback cannot start an unlocked writer. Do not steal a held lock, delete another process's `instance.json`, or fall back to an independent writer after an IPC failure.
3. When the lock is held elsewhere, extend `second_start` to dispatch an action separately from `raise_running`. Add provisional `forward_action` and loopback `/api/instance/action` with a dedicated random action token in `instance.json`; keep the raise token and ordinary second-start semantics unchanged. Use proxy-free urllib POST, constant-time token comparison, exact Host/method/content-type/body-size validation, reject Origin-bearing browser requests, provide no CORS permission and accept no cookie-only authentication on this endpoint. Restrict discovery credentials to the current user where supported; do not claim existing file permissions already enforce that. The generated file contains no bearer token.
4. The forwarding client creates a fresh request UUID per invocation and retains it across transport retries. The receiver atomically deduplicates a repeated UUID and returns the same admission/result ticket for five minutes. Separate invocations while an external action is pending attach to that result; after completion coalesce a two-second burst to avoid accidental double inversion. The receiver, not the file or forwarding client, reads intent and derives `enabled` and `expect` once. Never resend an uncertain request with a new UUID or automatically invert after `state_changed`. A crash after admission has an unknown result; report “Check the result in the App”, never claim exactly-once execution across crashes.
5. Admit on the existing service/job path. A new `submit_if_idle`-style primitive must atomically check all queued/running writers and the quit reservation under the JobRunner admission lock and enqueue the external toggle; do not implement a check-then-submit race. Coordinate with `classic.starting`, update-close admission and the existing classic queue. Reuse `Services.submit_toggle`'s shared work and `ModLibrary.toggle`, preserving pins, `expect`, consent, safety and journals. Do not acquire a non-reentrant JobRunner lock and then call its ordinary locking submit method. Recheck reasons on the worker. The external action refuses busy immediately; it does not create a delayed classic/game queue. Existing UI queue behaviour stays as it is.
6. The receiver owns the result and the notice. Return a ticket promptly; allow authenticated status polling for a bounded retained result, independently of the longer writer duration. A forwarding process exits after acknowledgement; it never terminates the resident App. If the lock owner is starting and has not published info, retry discovery for up to five seconds using the same UUID. An older App without the command capability refuses with “Open the updated App first”; it must not receive an ordinary raise and be mistaken for success. No acknowledgement means an unknown/unavailable result, not permission to run a second writer.
7. If no App runs, own the lock, build `Services`, API/server and command handling without `_run_window`. Start required watch/guard work and set deferred-startup state before the first library access; do not call `ready()` to warm the Hall, load Spine, launch tours, request new consents or start an update. Lazy library construction must not enqueue optional prune before this command and then falsely reject itself as busy. Reuse necessary recovery and the writer follow-up; stop/join optional scans during orderly shutdown. Record the actual job outcome, show only the result window, then stop services/server and release the lock. Keep the OS event loop alive until the worker and notice finish. A timeout or closing the progress surface cannot abandon a live writer; existing `Services.close`'s bounded shutdown alone is not sufficient proof of completion.
8. An ordinary App launch during this transient lifetime must promote the same process into the full App rather than lose the user's launch or create another writer. Route the ordinary raise to a “show main App” intent; create the full window on the UI thread, transfer lifetime ownership and cancel transient auto-exit. If the result window is already open, do not bind its close to `Services.quit` for the newly opened main App. Test the race between promotion and lock release.

**S:** `Services.library` currently can schedule startup prune/scan depending on `_startup_ready`; `start()` defers that until `ready()`. `Services.close` stops watches/scanner/classic and calls `jobs.shutdown(wait=...)`. **P:** The new transient host must account for these side effects instead of assuming `build()` plus `--serve` already provides a minimal, safe lifecycle. Preserve diagnostics/log redaction; redact the new token alongside the existing tokens.

### Outcome rules

All decisions in the following table are **P**; the inherited checks and partial-write semantics are **S**, described in section 1.

| Situation | Action and short notice |
| --- | --- |
| Ready; intent On or Off | Invert once using current receiver intent and `expect`. Show existing localized `mods.onState` / `mods.offState` only after completion qualifies as complete success. Zero configured changes is still a valid intent change if known installs exist. |
| Game running | Refuse before changing intent: existing `error.game_running` (“请先关闭游戏”). No wait-until-game-exits queue. If the game starts mid-operation, retain completed entries/recovery records and show a partial/failed result. |
| Process status unknown, Steam updating/verifying, classic UI open | Refuse with existing localized `game_status_unavailable`, `steam_busy` or `classic_open` reason. Recheck at writes. Never offer or silently create the classic deferred queue from the external file. |
| Any writer or quit/update reservation active | Refuse external admission with `error.busy`; attach to an already pending external invocation instead of reversing twice. This is intentionally stricter than the current normal UI's serial queue admission. Read-only work may continue through the single worker; no parallel game writer is introduced. |
| No selected folder, but another known install exists | Toggle the same known-install set as the service/tray. Do not limit the command to the visible server. |
| No known game folders at all | Refuse with `error.game_not_found`; leave intent unchanged. Keep generation available so the file may be created before the user configures the game. Do not invoke folder selection or first-run setup during external activation. |
| State/folder changed, profiles unreadable, lock contention | Show the mapped existing reason where it is useful; do not recompute the inverse and retry automatically. Translate a bounded writer-lock contention to busy. Existing metadata/transaction locks remain essential, but other data directories or non-cooperating tools are outside this admission check's scope. Do not promise exclusive access across all programs. |
| File locked, permission denied, low disk space, missing original/source, invalid bundle or failed rollback | Preserve existing protections and recovery. Show partial completion if any entries or intent changed; otherwise a refusal/failure. Name a short localized reason and direct the user to the App for details; never show a raw traceback. No automatic retry, restore-all or rollback of previously completed Mods. |
| Generation cancelled / generation fails | Cancel writes no launcher and changes no Mods. Compilation/COM/save failure removes only its own staging item and reports failure. A collision is left untouched; choose another folder or explicitly replace only a launcher proven to belong to this installation. Never recursively delete a same-named unknown `.app` bundle. |
| App cannot start or renderer/assets unavailable | If the App is running enough to report, show an OS-native alert with plain localized text. Existing `native.message_box` is a source-verified dependency-free fallback. If the OS blocks the App before it runs, only its OS prompt is possible. Missing M1 target is reported by the applet; a broken W1 target may be reported by Explorer. Do not guarantee an App notice when its executable never starts. |

**P:** Complete success requires a finished nonfailed job, the requested final intent, no unfinished `pending`/`left`/`stuck`, and no material `failed`/`left`/`stuck`/`skipped`/`dropped` outcome. Adoption without unfinished work may still be success, with details in the App. A `dropped` source or skipped damaged file must not produce an unqualified “Mod 已开启”. For a thrown stopping error, obtain the final persisted intent/status and report uncertainty/partial work; a success exit code cannot be inferred just from saved intent. Proposed process result codes: 0 complete/accepted forwarding, 2 refused, 3 partial/failed, 4 startup/transport/unknown. Forwarding code 0 means acknowledged handling, not that writes finished successfully.
