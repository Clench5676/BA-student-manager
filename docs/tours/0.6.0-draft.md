# 0.6.0 feature tour draft

**Draft only. Copy and image concepts await owner approval. Nothing here is published or packaged.**

Proposed order: photography, shared galleries, Hall viewing zoom, release notes. Student Hall itself and ZIP export
already shipped in 0.5.0; this draft does not introduce them again. Reconcile these cards with the final stable
0.6.0 feature set before approval. The current build remains 0.6.0-alpha.2.

The implemented default is **text-only**. Each page has an optional illustration slot, but this draft includes no
image files. If the owner wants illustrations, draw only the App's own UI controls, generic geometric placeholders
and neutral color blocks. Do not include screenshots, game characters, portraits, backgrounds, logos, atlas sprites
or any pixels derived from game files. A future runtime capture from the user's own install requires separate
implementation; this framework does not capture, scan, download or start a renderer for a tour.

The image concepts below describe optional App UI illustrations for review, not screenshots or approved assets.
The published registry remains empty until the owner approves every locale and any final illustration together.

## Owner review decisions

- Approve or revise the four feature IDs, order and all six copies against the final 0.6.0 scope.
- Keep text-only pages, or review completed App UI illustrations and captions before packaging them.
- Publishing a tour is an explicit source change to `webui/tours.py`'s `PUBLISHED_TOURS`, with `approved: True`.
  Each page needs `id`, six `copy` entries (`title`, `body`, optional `caption`) and an optional `/tours/<name>.png`
  illustration in the packaged web directory. The title/body limits are 80/320 characters; image captions fit one
  line and are limited to 40 characters. Missing/invalid images fall back to text. Pages without complete copy in
  all six locales are omitted. Revisions to an already presented release never create a new automatic prompt.
